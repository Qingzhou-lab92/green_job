# Career Desk · 个人求职工作台 MVP v2

React + TypeScript + Vite + Tailwind，浅绿 Liquid Glass 界面。无账号、无后端，个人资料保存在当前浏览器的 IndexedDB。AI 使用用户自行配置的 OpenAI-compatible 接口。

本轮业务逻辑按 `job_agent_mvp_v2_compact.md` 重构，保留原有视觉风格、原文档案和历史数据。实现与验证细节见 [MVP_V2_REPORT.md](./MVP_V2_REPORT.md)。

## 本地运行

建议 Node.js 22.13+，npm 10+。

```sh
npm ci
npm run dev
```

默认访问 http://127.0.0.1:5173 。首次进入为空工作区。“体验演示”会加载明确标记的虚构资料和模拟工作流；已有数据时需要确认替换。

```sh
npm test
npm run build
npm run preview
```

构建输出 `dist/`，静态预览默认 http://127.0.0.1:4173 。浏览器测试使用本机 Chrome，在开发服务器运行期间执行 `npm run test:e2e`。测试使用独立浏览器上下文、合成资料及拦截的 AI 响应，不读取真实个人资料或调用付费接口。

## v2 使用流程

1. **认识我**：导入 PDF、DOCX、TXT/Markdown 或粘贴文字，保存原文；填写补充信息；AI 拆解后检查事实、来源、偏好和推断，确认生成画像版本。原文历史单独保留。
2. **JD 拆解器**：粘贴 JD，AI 结构化，预览九个平铺字段、关键词及依据，确认保存。原文只读，修订时新增记录。
3. **岗位分析**：从自己的 JD、Excel/CSV 导入记录或内置 478 条历史岗位库中选择本次范围，生成报告。未结构化的记录先经 AI 处理，随后执行 Hard Gate 和逐项证据匹配。
4. **推荐**：模型判断 direct/general 及证据类型，代码计算 R/P/U/E。每类最多 3 个，总分必须大于 60、可评估权重至少 0.6；不足不补齐。可展开查看依据和分数贡献。
5. **简历精修**：从当前报告选择一个岗位，生成逐项改写建议。逐条接受或编辑后另存版本，可导出 TXT/Markdown，再加入投递看板。画像或 JD 变化会让报告过期，旧报告不能继续用于改写。
6. **投递看板**：五列拖拽，支持状态菜单、新增、编辑、删除和筛选。统一展示跟进/面试标签、未来七天安排及冲突提示。

概览、面试陪练及设置页保留。历史“笔试”记录读取时并入“已投递”，备注保留来源；旧待办数据仍可备份，但概览不显示待办清单。

**正式画像、JD、匹配与精修流程需要配置 API Key。** 未配置会引导到设置，不会静默使用旧正则评分。只有主动进入演示工作区才使用模拟流程；面试陪练保留明确标记的本地模拟反馈。

## AI 配置与隐私

在“设置与数据”填写可信服务商的 Base URL、模型名和自己的 API Key，保存配置。客户端请求 `<Base URL>/chat/completions`，使用 Bearer 鉴权和非流式响应，不需要环境文件。

- Key 只保存在当前站点的 localStorage，不进入代码、Git、构建产物或个人数据备份。localStorage 不是加密保险库；请使用可信设备、个人低额度密钥，并按需清除或轮换。
- 调用前显示目标服务商和请求数量并确认。相关简历、补充信息与 JD 直接发送给该服务商，不经过站点维护者的服务器。
- 四个业务节点要求严格 JSON，经 Zod、ID 和引用校验后才允许保存。接口、JSON 或校验失败保留原记录，提供重试，不回退为旧算法。
- 原始文本作为 `untrustedData` 传入固定系统任务，不执行其中命令，不执行 AI 返回的 HTML/脚本。模型仍可能误判语义，用户必须核对事实和改写。
- 服务商必须允许浏览器跨域 CORS；不允许时纯静态站点无法替其绕过。请求超时 60 秒；HTTPS URL 不允许嵌入账号密码或查询参数。
- 应用不含分析追踪、广告或远程字体。托管平台可能记录普通访问日志。

## 备份、恢复与导入

“设置与数据” → **导出全部数据** → 下载 JSON。包含原文档案、画像及确认版本、JD 快照、报告、选岗上下文、简历版本、投递和练习；不含 AI 配置和 Key。

恢复：选择 JSON → 查看预览 → **确认替换并恢复**。兼容旧 `schemaVersion: 1`；v2 新增可选 `workflow.version: 2`，旧画像不会自动变成已确认画像。校验失败不写库。备份包含个人信息，请妥善保存。

浏览器清理数据、隐私模式或设备损坏可能导致丢失，建议定期导出。不同浏览器、域名及端口拥有独立存储；迁移站点时先导出，再到新站点恢复。暂不支持多标签页同时编辑时的冲突合并。

- **投递 CSV**：设置页导入，UTF-8，必需列 `company,role`；可选 `city,source,date,status,followUp,interviewAt,notes`，预览后追加。日期 YYYY-MM-DD，面试时间 YYYY-MM-DDTHH:mm。CSV 不自动关联 JD/简历版本。
- **岗位 Excel/CSV**：岗位分析页导入 `.xlsx` 或 UTF-8 CSV，选择工作表、预览、确认并去重。支持中文/英文岗位名称、公司、地点、JD 原文、职责、要求、技能、硬性条件、加分项列，也支持 `job_profile_json`。可选 `match_category` 保存原库分类；它不代替模型基于用户画像重新分类。
- JSON/CSV 导入上限 10 MB，岗位表最多 1000 行、20 张工作表。旧 `.xls` 请另存为 `.xlsx`。
- **清空全部数据**：确认后清除本应用数据库及 AI 配置，不清除其他应用数据。

## Cloudflare Pages

1. 将项目推送到目标 GitHub 仓库。
2. Cloudflare 控制台 → Workers & Pages → Pages → 连接 Git 仓库。
3. 选择目标仓库及要部署的分支；根目录设为包含本文件与 `package.json` 的目录。
4. 构建命令 `npm run build`，输出目录 `dist`，Node.js 版本可设为 22。
5. 保存并部署；后续推送部署分支将触发构建。**不要配置 AI Key，尤其不要设置 `VITE_*` 密钥变量。**

也可本机构建后将 `dist` 上传到 Pages Direct Upload。不需要 Functions、Worker、D1 或后端。`public/_headers` 提供静态响应头，应用使用单入口内存导航。

## 静态部署与 MVP 边界

- PDF.js 提取 PDF 文字层，Mammoth 提取 DOCX 纯文本，均在本地执行。PDF worker、字体和字符映射随构建提供，不依赖 CDN。扫描 PDF OCR、密码解密、版式还原暂不支持，多栏顺序需要核对。
- 简历档案库保存提取文本和文件来源元数据，不保存原始二进制文件；请自行保留源文件。单份简历最多 15 MB、100 页 PDF、20 万字符。
- 内置 478 条岗位是历史快照，随站点公开，不保证仍在招聘。私人导入数据只在当前浏览器。批量 AI 请求按所选岗位顺序执行，可能耗时且产生费用，失败时整份报告不覆盖旧数据。
- 不提供登录、云同步、后台提醒、日历 API、招聘网站爬虫、自动投递或验证码绕过。无 Service Worker，不承诺断网首次打开或刷新可用。
- Hard Gate 对缺证据和无法可靠判定的复杂条件保留 CONDITIONAL；语义判断与事实真实性仍需人工核实。评分是可解释的建议，不是录用概率。

## 代码

`App.tsx` 保留导航、概览、投递、面试、设置和共用组件；`WorkflowPages.tsx` 实现四个 v2 业务页面；`workflow-model.ts` 扩展 Schema；`workflow.ts` 实现确认、Gate、计分、推荐和版本上下文；`prompts.ts` 集中四节点提示；`ai.ts` 管理 API；`schedule.ts` 集中时间规则。旧解析和评分函数保留用于历史兼容与测试，不进入正式匹配链路。
